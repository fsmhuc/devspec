# 三维验证（ds:verify）

> 验证实现是否真正匹配规格意图。补充现有 `validate` 的结构检查，增加语义级验证。

---

## 与 validate 的区别

| 维度     | `ds:validate`（现有）      | `ds:verify`（新增）          |
| -------- | -------------------------- | ---------------------------- |
| 检查层级 | 结构（文件存在、格式正确） | 语义（内容匹配、逻辑一致）   |
| 自动化   | 全自动                     | 半自动（生成检查清单供确认） |
| 适用时机 | 每次变更后                 | 功能完成时、发布前           |

---

## 三个验证维度

### 维度 1 — 完整性（Completeness）

**问题：所有承诺的工作是否都完成了？**

检查项：
- [ ] tasks.md 中所有任务状态为 `done`
- [ ] spec.md 中所有验收标准已勾选
- [ ] 必填节（由严格等级决定）是否都有内容
- [ ] 关联的 Delta 是否都已合并

自动化程度：**全自动** — 解析 Markdown checkbox 和任务状态

### 维度 2 — 正确性（Correctness）

**问题：实现是否匹配规格的意图？**

检查项：
- [ ] API 端点是否与 spec.md 中的接口定义一致
- [ ] 数据模型是否与 spec.md 中的定义一致
- [ ] 边界情况是否都有对应处理
- [ ] 测试用例是否覆盖所有验收标准

自动化程度：**半自动** — 生成对照清单，由 AI Agent 或人类逐项确认

### 维度 3 — 一致性（Coherence）

**问题：实现是否与系统整体设计协调？**

检查项：
- [ ] 功能设计是否符合 architecture.md 中的架构约束
- [ ] 功能间依赖是否与 spec 中声明的一致
- [ ] 是否引入了 spec 中未声明的依赖
- [ ] 命名和术语是否与 glossary.md 一致

自动化程度：**半自动** — 交叉引用检查 + 人工确认

## 使用方式

```bash
# 验证单个功能
python3 mcp/cli.py verify <feature-name>

# 验证所有功能
python3 mcp/cli.py verify --all

# 输出 JSON 格式（用于 CI）
python3 mcp/cli.py verify <feature-name> --format json
```

### CLI 别名

```
ds:verify → python3 mcp/cli.py verify
```

## 验证触发时机

| 时机               | 是否必须 |
| ------------------ | -------- |
| 功能开发完成       | ✅ 必须   |
| 发布前             | ✅ 必须   |
| PR 审查中          | 推荐     |
| 规格变更后         | 推荐     |
| 日常开发中         | 可选     |

---

## 与现有工具的关系

```
ds:validate ──> 结构正确性（文件存在、格式对、引用不断裂）
     │
     ▼
ds:verify ───> 语义正确性（内容匹配、意图一致、覆盖完整）
     │
     ▼
ds:loop ─────> 完整循环（验证 → 编译 → 波及分析 → 测试 → 分析）
```

| 依赖一致性         | ✅ 必查    | ✅ 必查    |
